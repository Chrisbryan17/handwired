# Eight Frontiers — shared GPU/graphics design
## Computation contract
CPU reference -> canonical packed state -> GPU storage buffers -> solver compute passes
-> Handwired-generated WGSL numerical kernels -> same resident state -> viewer shaders.
Stage input once; retain ping-pong state in GPU memory; only read back for explicit verification.
The Handwired `emitInlineCircuitWgsl` function generates numerical update logic and can be
called directly from domain-specific kernels. It is not a replacement for the all-pairs,
spatial hierarchy, collision or learned-policy algorithms surrounding it.
Never label domain-specific handwritten WGSL "generated by Handwired".

## Shared boundaries
- `src/runtime/frontiers-device.ts`: strict WebGPU adapter acquisition, diagnostics,
resource accounting and no hidden CPU/software fallback.
- Domain models: deterministic scenario seeds, references and scientific units.
- Domain GPU solvers: owned buffers and pipelines, explicit `dispose`, finite-state checks.
- Domain viewers: camera navigation, GPU-resident draw, optional periodic telemetry.
- Deployment: existing `scripts/demo-site-pages.ts` route registry and Pages workflow.
- Verification: numerical oracle comparisons, synchronized GPU completion/readback,
independently executed browser smoke, adapter vendor/architecture reporting, real screenshot.
- Future common kernels: uniform spatial grid, radix sort, AABB/BVH builder, 3D camera,
timing query instrumentation, resource allocator, bounded worker scheduler.

## Physics and scientific boundaries
Earth: OSM data != live traffic. Model flow and synthetic scenario outputs explicitly.
Cataclysm: numerical fluid constraints != validated city-scale tsunami prediction.
Genesis: cellular dynamics != biologically evolved organisms absent actual selection/training.
Universe: softened Newtonian particle N-body != full cosmological galaxy formation.
Reality: SfM calibration != guaranteed metric scale; measurements need calibrated units.
Destruction: constrained particle fracture != civil engineering structural certification.
Light: Monte Carlo estimate requires linear energy-conserving BRDF and convergence checks.
Machines: trained controller != validated contact solver or sim-to-real transfer.

## Development sequencing
First: strict device, independent CPU N-body, GPU pairwise solver + Handwired step, on-device point renderer.
Then: reusable 3D projection/geometry, spatial index, GPU timing telemetry, generative field compute.
Then parallel domain-specific solvers, data ingestion, reconstruction, articulated physics.
